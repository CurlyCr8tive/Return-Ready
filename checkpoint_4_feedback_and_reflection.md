# Checkpoint 4 — Feedback and Terminal vs IDE Reflection

## Artifact
A specific example of feedback changing in the terminal was when I needed Aider to understand the digest flow. In VS Code, I would have clicked between the homepage, digest detail page, and API type definitions to understand the relationship visually. In the terminal, I had to explicitly add the relevant files and describe what I wanted it to focus on.

Instead of relying on visual context, I had to communicate in words which files mattered and what relationship I wanted the AI to understand.

## Reflection
Yes, the terminal forced me to be more precise because I couldn’t just point at code, highlight a section, or say “this part right here.” I had to describe the problem in words and be more specific about the flow, the component, or the behavior I was talking about.

What’s better about building from the terminal is that it forces more intentional thinking. I had to be clearer about context, clearer about what I wanted, and more deliberate about planning before moving. What’s worse is that it feels slower and less natural for me right now. I’m used to the file tree, quick visual orientation, and being able to jump between files easily in VS Code.

I would not fully switch from my current IDE setup. I’d still want VS Code as my main environment because that’s where I feel most comfortable actually reading, editing, and verifying code. But I do see the value of the terminal workflow for planning, scoping, and forcing clearer communication with the AI. So I would use it as a complementary workflow rather than a replacement.
